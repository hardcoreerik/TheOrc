# Phase 0 — Reference Oracle

## Mission

Phase 0 makes “correct” measurable before OrcEngine computes a model token. It produces immutable reference inputs and outputs, a comparison runner, and a failure-localization protocol.

## Why this precedes implementation

A wrong inference engine can generate fluent text. Final output alone cannot distinguish mistakes in tokenization, weight orientation, normalization, RoPE, attention grouping, masking, cache positions, precision, or sampling. Phase 0 turns those ambiguities into independently comparable checkpoints.

## Oracle topology

Use three independence classes:

1. **Independent ground truth:** hand-derived operator microcases and tiny synthetic values whose expected outputs are not generated by either inference framework.
2. **Primary semantic oracle:** a pinned Python implementation using NumPy and/or PyTorch, kept explicit enough to capture every named intermediate.
3. **Secondary deployment oracle:** pinned llama.cpp for GGUF interpretation and end-to-end token comparison.

No oracle is infallible. Agreement across the three independence classes, source configuration, and conversion metadata is stronger than copying one engine’s behavior blindly.

The exact synthetic mathematics and selected real-model candidate are in [Phase 0 Architecture Profile](PHASE_0_ARCHITECTURE_PROFILE.md). Completion is evaluated through [Phase 0 Acceptance Contract](PHASE_0_ACCEPTANCE.yaml).

## Fixture ladder

### Fixture A: operator microcases

Tiny arrays with hand-verifiable outputs for matmul, RMSNorm, softmax, RoPE, masking, SiLU, elementwise multiply/add, and embedding lookup.

### Fixture B: synthetic one-layer model

Deterministic seeded weights, tiny vocabulary, tiny embedding, one layer, grouped-query attention if applicable, and a short token sequence. All tensors are small enough to inspect.

### Fixture C: synthetic multi-layer/cache model

At least two layers and enough tokens to validate prompt evaluation versus incremental cached decode.

### Fixture D: pinned real model

Small real artifact with exact source, conversion, tokenizer, and license record.

## Required capture points

For each token position and layer:

- input embedding;
- pre-attention normalized state;
- Q, K, and V projections;
- Q and K after RoPE;
- selected cache slice after write;
- masked attention scores for a small fixture;
- attention probabilities;
- attention output before and after output projection;
- post-attention residual;
- pre-FFN normalized state;
- gate and up projections;
- activated/gated product;
- down projection;
- post-FFN residual;
- final normalized state;
- logits;
- selected token and top-token margin.

For the real model, full capture may be too large. Always retain layer boundaries; enable deep taps around the first mismatch.

## Comparison record

Every tensor comparison reports:

- name, layer, position, dtype, shape, and strides;
- expected and actual hashes;
- max absolute error and index;
- max relative error and index;
- mean absolute error;
- NaN and infinity counts;
- optional cosine similarity;
- pass/fail under the named tolerance profile.

Every retained tensor artifact also records byte strides, logical layout, endianness, and contiguous/non-contiguous status. Shape alone is insufficient to diagnose transposition and view errors.

Integer, byte, shape, metadata, and token-ID comparisons require exact equality.

## Tolerance policy

Do not define a universal epsilon before data. Establish per-operator profiles by:

1. running the primary oracle repeatedly;
2. controlling dtype and deterministic settings;
3. comparing alternate valid operation orderings;
4. recording CPU/library/version effects;
5. choosing bounds tight enough to catch seeded faults;
6. documenting why each bound exists.

Tolerance changes require a decision-log entry and before/after failure evidence. A tolerance may not be widened solely to make a test green.

## Determinism controls

- fixed model and tokenizer hashes;
- fixed raw input bytes and token IDs;
- fixed seed even when greedy mode should not consume randomness;
- evaluation mode with training features disabled;
- fixed thread/library settings where possible;
- pinned dependencies and compiler flags;
- explicit float32 execution;
- no stochastic tokenizer sampling;
- greedy argmax with documented tie behavior.

At least one fixture must deliberately create near-tied top logits. It records both logits, their margin, the selected token, and the exact-tie rule; token agreement alone cannot pass this fixture.

## Tokenizer reconciliation

Generate token fixtures independently through the pinned source tokenizer and the tokenizer reconstructed from converted GGUF metadata. Compare rendered prompt bytes, token IDs, decoded bytes, special-token behavior, and hashes exactly. Any unexplained disagreement rejects the real-model candidate; it is not normalized away in the harness.

## Cache equivalence test

For token sequence `[t0, t1, ... tn]` compare:

1. full-prefix evaluation producing logits at `tn`;
2. prompt evaluation through `t(n-1)` plus one cached decode of `tn`.

The last-position states and logits must meet the approved profile. Repeat with context reset to catch stale state.

## Fault-injection proof

The oracle harness is not accepted until it detects at least:

- one transposed projection matrix;
- one off-by-one position;
- one incorrect RoPE pairing;
- one missing causal mask;
- one swapped K/V cache write;
- one changed RMSNorm epsilon;
- one tokenizer special-token error.

## Failure triage

Find the earliest mismatching checkpoint. Do not patch downstream symptoms.

```text
tokens differ -> tokenizer/template/special tokens
embedding differs -> token ID or embedding layout
pre-attn norm differs -> RMSNorm
Q/K/V differs -> weight mapping or matmul layout
post-RoPE differs -> position/frequency/layout
attention differs -> mask/grouping/scale/cache
FFN differs -> projection mapping/activation/gating
only cached path differs -> cache write/read/position ownership
only token differs -> logits margin/argmax/sampler
```

## Phase exit gate

Phase 0 is complete only when the full bundle can be regenerated from documented commands, hashes match, deliberate faults fail at expected checkpoints, provenance is complete, an independent reviewer can reproduce at least the synthetic bundle, and every required entry in [Phase 0 Acceptance Contract](PHASE_0_ACCEPTANCE.yaml) is explicitly `pass`. A missing, unknown, or skipped result is a failure.
